# TransitGo for Business — 竹北企業通勤（第一個客群）

> 狀態：規劃文件，尚未實作。所有「假設」都要靠訪談驗證，不是事實。
> 前提：單人開發、無法務、Render 免費方案（512 MB）、不碰即時接駁車 GPS。

## 1. 為什麼先做竹北

- 竹北（高鐵新竹站、台鐵竹北站、六家、生醫園區、光明六路一帶）通勤者多，公司集中，且已有真實資料可查：
  台鐵、高鐵、新竹縣／市公車、跨區客運、YouBike（新竹縣市站點皆在圖中）。
- 生醫園區、高鐵特區一帶大眾運輸班次稀疏，「最後一哩」（高鐵／台鐵 → 公司）是最明顯的痛點，
  而 TransitGo 已有「步行＋YouBike＋公車＋鐵路」的組合路線，這正好對上。
- 一個城市、一種客戶（企業人資／行政），比同時做校園、政府單純。

## 2. 產品定位（一句話）

給竹北中型企業的**員工通勤路線頁**：公司放一個連結（或 QR），員工輸入出發地，就看到「到公司最快、最穩」的
大眾運輸＋YouBike 組合與實際班次。

不是接駁車 GPS、不是員工打卡、不追蹤員工。

## 3. 目標客戶與買單者

| 角色 | 想要什麼 | 我們能給什麼（現有能力） |
|---|---|---|
| 人資／行政 | 新人報到、招募說明「怎麼來公司」；減少停車位與交通津貼糾紛 | 公司專屬通勤頁、招募用連結 |
| 員工 | 早上知道幾點出門、公車有沒有來 | 多模式路線、即時到站、YouBike 車輛數 |
| 主管／廠務 | 上下班時間的交通資訊 | 依上班時間預設查詢（08:30 到、17:30 走） |

首批對象假設：50–500 人、沒有自營接駁車或只有 1–2 條、位於高鐵特區／生醫園區／六家一帶的公司。

## 4. MVP 範圍（Phase 3 對應）

**做**
1. 公司設定：公司名稱、地址（一個座標）、上下班時間、可選的「附近推薦下車站」。
2. 公司通勤頁（Web，手機優先）：輸入起點 → 呼叫現有 `POST /api/v1/routes`，預設到達時間 = 上班時間。
3. iOS App 內「上班／下班」兩個常用旅程模板（沿用 Favorite Trips）。
4. 匿名彙總（可選、需公司同意）：查詢次數、最常見起點行政區——不含個人識別。

**不做（本階段）**
- 接駁車即時位置、司機端 App。
- 員工個人搭乘統計、位置追蹤、出勤關聯。
- 付款、計費、發票。
- 任何未成年人資料（Campus 另案，需先有法務意見）。

## 5. 需要新增的後端能力（尚未存在）

現況：`transitgo-server` 沒有租戶、沒有帳號、沒有 API key。最小做法：

| 項目 | 最小做法 | 備註 |
|---|---|---|
| Tenant | `companies` 表：id、name、lat/lng、work_start、work_end、slug | 先用手動 SQL／admin API 建立 |
| 公司頁 | `GET /c/:slug` 回靜態頁，呼叫既有路線 API | 不需要員工登入 |
| 存取控制 | 公司頁用不可猜的 slug；路線 API 加簡單 rate limit | 先不做 API key |
| 統計 | 只記錄 (company_id, 日期, 起點行政區, 次數) | 不存座標與裝置 ID |

**風險**：Render 免費方案 512 MB，圖載入後約 315 MB；加租戶功能本身很小，但流量增加要先量測，
第一個付費客戶前應升級方案。

## 6. 商業模式假設（待訪談驗證）

- 每公司月費（例如依人數分級）——**金額不預設**，用訪談問「你現在花多少在交通津貼／接駁」來定。
- 試用期免費 1–2 個月，用查詢量證明價值。
- 不賣個資、不賣廣告。

## 7. 訪談大綱（30 分鐘，對象：人資／行政）

**A. 現況（10 分）**
1. 員工目前怎麼通勤？（自駕／機車／大眾運輸／公司接駁）你們怎麼知道？
2. 新人報到時，怎麼告訴他們怎麼來公司？有文件嗎？
3. 最近一年有多少次「員工抱怨交通」或「遲到因交通」？大概什麼原因？
4. 有接駁車嗎？成本大概多少？誰在管？

**B. 痛點（10 分）**
5. 高鐵／台鐵到公司最後一段，員工怎麼解決？
6. 停車位、機車位夠嗎？交通津貼怎麼發？
7. 加班／彈性上下班時，交通資訊有問題嗎？

**C. 解法試探（10 分）**（給看現有 App 的路線畫面，不承諾功能）
8. 如果員工有一個「到公司」專屬頁面，你會放在哪裡（招募頁／新人手冊／內網）？
9. 你會想看什麼統計？（先問，不要先提個人層級的）
10. 這件事誰決定、誰付錢、預算大概哪一級？
11. 需要什麼才能在 1 個月內試用？

**判準（Phase 1 結束時要能回答）**
- ≥ 5 家訪談中，有幾家說「這是我們真的有的問題」且願意試用？
- 誰買單、預算等級？
- 最常被要求、但我們目前沒有的功能是什麼？

## 8. 資料與隱私邊界

- 起點座標只在單次路線查詢中使用，不存。
- 統計只存彙總，不存可還原個人的資料。
- 不對員工做任何追蹤；公司看不到「誰」查了什麼。
- 公司頁需有隱私說明（一頁式）；正式收費前請律師或專業人士看過條款——目前沒有法務，這是已知風險。

## 9. 時程（單人）

| 階段 | 內容 | 前提 |
|---|---|---|
| Phase 0 | 穩定正式環境（已完成：圖重建、記憶體 315/512 MB） | 完成 |
| Phase 1 | 訪談 5–10 家竹北企業，驗證 §7 判準 | 使用者安排 |
| Phase 2 | tenant 表＋公司頁＋簡單 rate limit | Phase 1 有 ≥ 2 家願意試用 |
| Phase 3 | 試用、看用量、決定收費 | 升級 Render 方案 |

## 10. 未驗證／已知限制

- 沒有票價資料（fare = null）。
- 公車沒有誤點秒數；高鐵沒有即時。
- YouBike 時間／距離是估算。
- 導航功能尚未在真機與背景模式驗證。
- 本文件的客戶輪廓、價格與需求全是假設，未經訪談。
